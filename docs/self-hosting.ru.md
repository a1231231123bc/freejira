# Freejira: установка и эксплуатация

## Быстрый запуск

Требуется **Node.js 24+** (проверено на Node.js 26).

```bash
npm ci
npm run build
npm start
```

Откройте **http://localhost:4173**. Первый пользователь создаёт пространство и становится владельцем. Можно добавить демонстрационные проекты при регистрации; по умолчанию пространство пустое. Готовых аккаунтов и стандартных паролей нет.

Для разработки: `npm run dev`. Браузер и API работают на одном порту. Данные сохраняются между перезапусками в `data/freejira.sqlite`.

## Что можно делать

- **Обзор:** прогресс по проектам, задачи в работе, просроченные сроки, ближайшие задачи и история действий команды.
- **Проекты:** название, уникальный код, описание, цвет, целевая дата, состояние, избранное и архив. Архивирование сохраняет данные; восстановление — через настройки проекта.
- **Задачи:** канбан с перетаскиванием и таблица, пять статусов, четыре приоритета, ответственный, срок, метки и описание. Фильтры по проекту, участнику, статусу, приоритету и просроченным срокам.
- **Личный фокус:** «Мои задачи» собирает назначения из всех неархивных проектов.
- **Совместная работа:** отдельные аккаунты, персональные одноразовые приглашения на 7 дней, комментарии и история изменений. Другие клиенты получают изменения при обновлении данных каждые 10 секунд и при возвращении на вкладку. Несовместимые одновременные правки отклоняются с объяснением, вместо молчаливого перезаписывания.
- **Поиск:** `⌘K` / `Ctrl+K` ищет проекты и задачи, включая архив; `C` открывает создание задачи. Для передачи задачи коллеге скопируйте ссылку в её окне.
- **MCP:** 11 инструментов, ресурс сводки, Streamable HTTP и stdio. Изменения через AI видны в том же интерфейсе и отмечены в истории.
- **Данные:** JSON-экспорт проектов, задач, комментариев и истории; отдельная команда согласованной резервной копии SQLite.

Владелец приглашает и отключает участников, меняет название пространства. Все активные участники видят и редактируют общие проекты; приватные проекты и отдельные права на каждый проект пока не реализованы. Приглашения передаются ссылкой: автоматической отправки email нет. Продукт предназначен для одной команды на экземпляр сервера.

## Общий доступ

### Локальная сеть

Сначала создайте владельца через локальный адрес, затем перезапустите приложение с сетевыми параметрами. Вместо `192.168.1.10` укажите IP компьютера в вашей сети:

```bash
HOST=0.0.0.0 PUBLIC_URL=http://192.168.1.10:4173 npm start
```

Все участники должны открывать **один и тот же адрес**, указанный в `PUBLIC_URL`. Приглашения создавайте по этому адресу: ссылка на localhost работает только на том же компьютере. Для доступа через интернет используйте HTTPS и обратный прокси.

### Docker на сервере

```bash
docker compose up -d --build
```

Контейнер доступен на `127.0.0.1:4173` сервера. SQLite хранится в постоянном Docker volume `freejira_data`; обычное пересоздание контейнера не удаляет данные. **Не выполняйте `docker compose down -v`, если хотите сохранить базу.**

Для публичного домена создайте `.env`:

```dotenv
PUBLIC_URL=https://projects.example.com
SECURE_COOKIES=true
TRUST_PROXY=1
```

Поставьте HTTPS-прокси, например Caddy, на том же сервере:

```caddyfile
projects.example.com {
    reverse_proxy 127.0.0.1:4173
}
```

`TRUST_PROXY=1` предполагает ровно один доверенный прокси и закрытый от прямого внешнего доступа порт приложения. Не открывайте первоначальную регистрацию в публичный интернет до создания владельца. Dockerfile подготовлен; в текущем окружении Docker-сборка не запускалась.

### Настройки окружения

Команды Node автоматически читают `.env`, если файл существует. Переменные окружения процесса имеют приоритет.

| Переменная       | По умолчанию            | Назначение                                   |
| ---------------- | ----------------------- | -------------------------------------------- |
| `PORT`           | `4173`                  | Порт HTTP                                    |
| `HOST`           | `127.0.0.1`             | Адрес привязки; для общего сервера `0.0.0.0` |
| `DATA_DIR`       | `./data`                | Каталог SQLite; нужен постоянный диск        |
| `PUBLIC_URL`     | Адрес входящего запроса | Канонический адрес для проверки Origin       |
| `SECURE_COOKIES` | `false`                 | Включить для HTTPS                           |
| `TRUST_PROXY`    | `0`                     | Число доверенных обратных прокси             |

Запускайте один экземпляр приложения с локальным постоянным SQLite-диском. Горизонтальное масштабирование, сетевые файловые системы и ephemeral/serverless-диски не поддерживаются этой конфигурацией.

## Подключение MCP

1. Откройте **MCP и AI** в приложении.
2. Создайте личный токен с правами **только чтение** или **чтение и редактирование**.
3. Сохраните токен: он показывается только один раз. На сервере хранится SHA-256-хеш.
4. Подключите клиент одним из способов ниже.

### Streamable HTTP

Endpoint: `https://projects.example.com/mcp` (локально `http://localhost:4173/mcp`). Заголовок: `Authorization: Bearer fj_...`.

Пример для клиентов, поддерживающих `mcpServers`, HTTP URL и пользовательские заголовки:

```json
{
  "mcpServers": {
    "freejira": {
      "url": "http://localhost:4173/mcp",
      "headers": { "Authorization": "Bearer YOUR_FREEJIRA_TOKEN" }
    }
  }
}
```

Названия полей в конфигурации могут отличаться между клиентами. Сервер использует [официальный MCP TypeScript SDK](https://ts.sdk.modelcontextprotocol.io/server) и транспорт Streamable HTTP, с JSON-ответами и без серверных сессий. OAuth и устаревший SSE transport не реализованы; клиент должен уметь передать Bearer token или использовать stdio-мост.

### stdio

Мост работает с тем же HTTP-сервером и не открывает базу напрямую. Пример конфигурации stdio-клиента:

```json
{
  "mcpServers": {
    "freejira": {
      "command": "/absolute/path/to/node",
      "args": [
        "--import",
        "/absolute/path/to/freejira/node_modules/tsx/dist/loader.mjs",
        "/absolute/path/to/freejira/server/stdio.ts"
      ],
      "env": {
        "FREEJIRA_URL": "http://localhost:4173",
        "FREEJIRA_TOKEN": "YOUR_FREEJIRA_TOKEN"
      }
    }
  }
}
```

Замените абсолютные пути на свои (`which node` покажет путь к Node). Сам сервер приложения должен работать. Для запуска из терминала:

```bash
FREEJIRA_URL=http://localhost:4173 FREEJIRA_TOKEN=YOUR_FREEJIRA_TOKEN npm run --silent mcp
```

Токен даёт доступ к текущему общему пространству от имени своего пользователя. Отключение участника отзывает все его сеансы и токены. Токен можно отдельно отозвать в интерфейсе. Токены без срока действия: отзывайте их после использования и не добавляйте в Git.

### Инструменты

| Инструмент                          | Возможность                                        |
| ----------------------------------- | -------------------------------------------------- |
| `workspace_summary`                 | Прогресс, просроченные задачи, последние изменения |
| `list_projects` / `get_project`     | Список проектов и детали с задачами                |
| `create_project` / `update_project` | Создание, обновление, архивирование проекта        |
| `list_tasks` / `get_task`           | Поиск, фильтры, задача с комментариями             |
| `create_task` / `update_task`       | Создание и редактирование задач                    |
| `add_comment`                       | Комментарий к задаче                               |
| `list_members`                      | Активные участники для назначения                  |

Ресурс: `freejira://workspace/summary`. Для обновления нужен `revision`, полученный при чтении актуальной задачи или проекта. Даты: `YYYY-MM-DD`. Удаление задач через MCP намеренно не предоставлено; оно доступно в интерфейсе с подтверждением.

## Резервные копии

JSON-экспорт полезен для переноса данных, но не восстанавливает аккаунты и не является полной резервной копией. Для полного восстановления:

```bash
npm run backup
# Или укажите новый файл:
npm run backup -- /safe/location/freejira-2026-10-27.sqlite
```

Команда использует SQLite Online Backup API: можно выполнять при работающем сервере. Существующий файл не перезаписывается. Храните копии вне диска сервера; они содержат хеши паролей и доступов.

В Docker:

```bash
docker compose exec freejira npm run backup -- /app/data/backup.sqlite
docker compose cp freejira:/app/data/backup.sqlite ./freejira-backup.sqlite
```

Для восстановления остановите приложение, сохраните текущую базу отдельно и замените `freejira.sqlite` резервной копией. При восстановлении не переносите старые `freejira.sqlite-wal` и `freejira.sqlite-shm`: отложите их вместе со старой базой, чтобы они не применились к восстановленной. Затем запустите приложение.

## Проверки

```bash
npm test             # API, права, приглашения, SQLite, HTTP MCP и stdio
npm run build        # TypeScript и production-сборка
npx playwright install chromium  # один раз, если браузер не установлен
npm run test:ui      # полная совместная работа в браузере + мобильный экран
```

Браузерный сценарий создаёт изолированную временную базу и запускает production-сервер на порту 4180. Пользовательские данные не затрагиваются. Скриншоты и трассировки — в `test-results/`.

Стек: React + TypeScript + Vite, Express, встроенный SQLite Node.js, Zod, официальный MCP SDK. Шрифты поставляются вместе с приложением: внешние сервисы для работы интерфейса не нужны.
